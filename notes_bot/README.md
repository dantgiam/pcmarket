# Личный ассистент по чату заметок

Отдельный бот, отдельный сервис Railway, отдельная база. С ботами магазинов
(`bot2`, `bot3`) не связан ничем, кроме ключа DeepSeek — их падение его не
трогает, его падение не трогает их.

## Как он работает

Каждое сообщение в чате заметок **один раз** проходит через DeepSeek и
превращается в строку SQLite: тип, проект, теги, краткая суть, срок, статус.
Дальше любой отчёт — это SQL, а не новый запрос к модели. Поэтому отчёты
мгновенные, история не переклассифицируется по кругу, а расход на модель
линеен количеству новых заметок.

Отвечает бот **реакцией**, а не сообщением, — чат заметок остаётся чистым:

| Реакция | Значение |
|---|---|
| 👀 | принял, разбираю |
| 🤔 | мысль |
| 🫡 | задача |
| ✍ | цитата |
| 🔥 | материал для контента |
| 🆒 | ссылка |
| 💯 | факт, справка |
| 🤷 | не смог разобрать |
| 🏆 | отмечено сделанным |

Telegram разрешает ботам только эмодзи из своего фиксированного набора —
привычные 💡📌✅ в него не входят. Поменять можно в `config.py`, список
допустимых там же в комментарии.

## Что он умеет

**Исправления.** Ответь реплаем хэштегами — `#задача #адыгид`. Классификация
перезапишется, а исправление ляжет в таблицу `corrections` и будет
подмешиваться в промпт как пример. Статусы там же: `#сделано`, `#выкинуть`.

**Правила.** Когда исправлений накопится достаточно, бот сам выведет из них
закономерность («заметки про водопады относи к adygid») и спросит кнопкой,
добавить ли её в постоянные правила. Подтверждённые правила видны в `/rules`.

**Запросы через «бро».** Сообщение, начинающееся с «бро», — не заметка, а
вопрос к базе:

```
бро, итоги дня
бро, что по адыгиду за неделю
бро, какие задачи висят
бро, что я забросил
бро, найди про пещеру возле Каменномостского
бро, цитаты за август
```

**Дайджесты.** Утренний (что прилетело за сутки, открытые задачи с кнопками
«сделано / выкинуть») и недельный: сводка, контент-план по каждому проекту
из накопленных заготовок, забытые идеи, предложения объединить дубликаты.
Проверить, не дожидаясь расписания: `/digest` и `/weekly`.

**Дубликаты.** Бот только предлагает: показывает, что и почему считает
повтором, объединяет — по кнопке. Свёрнутые заметки не удаляются, а
помечаются `merged_into` и перестают попадать в выборки.

## Настройка

### 1. Бот

У @BotFather: новый бот → токен. Затем `/setprivacy` → **Disable** и сделать
бота админом чата заметок (иначе он увидит только команды).

### 2. Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `NOTES_BOT_TOKEN` | да | токен от BotFather |
| `NOTES_OWNER_ID` | да | твой Telegram user_id — все остальные игнорируются |
| `NOTES_CHAT_ID` | да | id чата заметок, для супергруппы вида `-100…` |
| `DEEPSEEK_API_KEY` | да | тот же ключ, что у ботов магазинов |
| `NOTES_DB_PATH` | на Railway да | путь к базе, например `/data/notes.db` |
| `DEEPSEEK_MODEL` | нет | по умолчанию `deepseek-v4-flash` |
| `NOTES_TZ` | нет | по умолчанию `Europe/Moscow` |
| `NOTES_DAILY_HOUR` | нет | час утреннего дайджеста, по умолчанию 9 |
| `NOTES_WEEKLY_HOUR` / `NOTES_WEEKLY_WEEKDAY` | нет | по умолчанию 20:00 в воскресенье (0 = пн) |
| `NOTES_DAILY_ENABLED` / `NOTES_WEEKLY_ENABLED` | нет | `0` выключает дайджест |
| `NOTES_FORGOTTEN_DAYS` | нет | через сколько дней идея считается забытой, по умолчанию 30 |

Не знаешь свой `user_id` и `chat_id` — запусти бота без них: на любое
сообщение он ответит нужными значениями.

### 3. Railway

Новый проект → этот же репозиторий → в настройках сервиса **Root Directory =
`notes_bot`**. Тогда сервис увидит только эту папку с её `requirements.txt`
и не потянет зависимости ботов магазинов.

**Том обязателен.** Файловая система контейнера эфемерная: без тома вся
структурированная история сотрётся при первом же редеплое. Добавь Volume с
точкой монтирования `/data` и поставь `NOTES_DB_PATH=/data/notes.db`.

## Импорт истории

Bot API не отдаёт сообщения, отправленные до появления бота в чате, поэтому
история заливается из экспорта.

**Шаг 1.** Telegram Desktop → чат заметок → ⋮ → Экспорт истории чата →
формат **JSON**. Медиа можно не выгружать: текст и подписи в экспорте есть,
а фотографии бот всё равно берёт из самого Telegram.

**Шаг 2, самый простой — прислать `result.json` файлом прямо в чат заметок.**
Бот скачает его, посчитает сообщения и спросит кнопкой, импортировать ли.
Дальше зальёт в базу и прогонит через модель, продолжая принимать новые
заметки. Ограничение Telegram на скачивание ботом — 20 МБ; экспорт без медиа
укладывается в него даже на десятках тысяч сообщений.

**Шаг 2 (альтернатива) — с компьютера**, если экспорт больше 20 МБ или
хочется распознать текст на выгруженных фото:

```bash
cd notes_bot
python -m venv .venv && .venv/Scripts/activate     # Windows
pip install -r requirements.txt

set NOTES_DB_PATH=D:\Bots\PolPrivBot\notes_bot\notes.db
set DEEPSEEK_API_KEY=...

python import_history.py result.json --dry-run     # посмотреть, что попадёт
python import_history.py result.json               # залить и разобрать
python import_history.py result.json --ocr         # ещё и распознать фото
python import_history.py --classify-only           # дозапустить разбор
```

Импорт идёт в два прохода: сначала всё складывается в базу, потом
неразобранное уходит в модель пачками. Прерывать и перезапускать можно
сколько угодно — чекпоинт это само поле `type`, уже разобранное второй раз в
модель не пойдёт. Повторный импорт того же файла ничего не задваивает:
уникальность держится на паре `(chat_id, message_id)`, и по ней же импорт
стыкуется с живым потоком.

Если импортируешь локально, а бот работает на Railway с томом, — базу потом
никак не переложить в контейнер. Поэтому для Railway пользуйся способом с
присланным файлом.

## Файлы

| Файл | Что внутри |
|---|---|
| `main.py` | бот: приём заметок, реакции, «бро», кнопки, расписание |
| `db.py` | схема SQLite, FTS5-поиск, все выборки |
| `classify.py` | промпт классификатора, few-shot из исправлений, правила |
| `commands.py` | «бро, …» → фильтр → SQL → человеческий ответ |
| `digest.py` | дайджесты, контент-план, дубликаты, вывод правил |
| `deepseek.py` | клиент DeepSeek с ретраями и устойчивым разбором JSON |
| `ocr.py` | распознавание текста на скриншотах |
| `import_history.py` | импорт JSON-экспорта, он же CLI |

## Известные ограничения

- **Голосовые и кружки не расшифровываются.** Они сохраняются с пометкой
  `needs_transcription` и получают 🤷 — то есть не теряются, но и не
  разбираются. Нужен отдельный Whisper, DeepSeek аудио не принимает.
- **Поиск без морфологии.** FTS5 ищет по обрезанной основе слова
  («пещеру» → «пещер»*), что покрывает большинство случаев, но не все.
  Если начнёт мазать — следующий шаг это эмбеддинги.
- **Дайджест приходит в тот же чат заметок.** Если начнёт мешать — вынести
  в отдельный чат отчётов.
